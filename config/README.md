# intronIC Configuration Files

This directory contains configuration files for intronIC.

## Two Types of Configuration

### 1. TOML Config (General Settings)
**File:** `default.toml` (example template)
**Option:** `--config`
**Format:** TOML
**Purpose:** General intronIC settings (threshold, scoring regions, output options, performance)

### 2. YAML Optimizer Config (Training Settings)
**Files:** `training_default.yaml`, `training_fast_test.yaml`, `training_quick.yaml`
**Option:** `--optimizer-config`
**Format:** YAML
**Purpose:** SVM hyperparameter grid search settings (only used during training)

---

## TOML Configuration (General Settings)

### `default.toml` - Example Template

This is an example TOML config file showing all available general settings. It's generated by `intronIC --generate-config`.

**Settings include:**
- **Scoring:** threshold, PWM scoring regions, pseudocount
- **Output:** naming conventions, file formats
- **Performance:** parallel processes, min intron length
- **Isoforms:** isoform selection, duplicate handling
- **Training:** n_models, eval_mode, cv_folds (basic settings)
- **Advanced:** random seed, debug mode

### Usage:

**Generate a template:**
```bash
intronIC --generate-config
# Creates ./.intronIC.toml in current directory
```

**Use a custom config:**
```bash
# Specify config file location
intronIC classify -g genome.fa -a annotation.gff -n species \
  --config path/to/my_config.toml

# Or place in one of the auto-detected locations:
# 1. ./.intronIC.toml (current directory)
# 2. ~/.config/intronIC/config.toml (user config)
# 3. ~/.intronIC.toml (user home)
```

**Example use case:** Set project-wide defaults for threshold, parallel processes, and output naming without repeating CLI args.

## YAML Optimizer Configurations (Training Settings)

### `training_default.yaml` - Production Default
**Use for:** Production runs, publications, final analysis

Matches the original hardcoded production defaults:
- **Rounds:** 5 geometric refinement rounds
- **CV folds:** 5-fold cross-validation
- **Grid size:** 144 combinations per C value
- **Max iterations:** 100,000 (ensures convergence)
- **Estimated runtime:** 60-120 minutes (full genome), 20-40 min (Chr19)
- **Estimated CV fits:** ~9,360

This is the most thorough configuration and should be used when you need
publication-quality results or are analyzing a new species.

### `training_fast_test.yaml` - Fast Testing
**Use for:** Feature development, quick validation, testing changes

Reduced complexity for faster iteration:
- **Rounds:** 3 refinement rounds
- **CV folds:** 3-fold cross-validation
- **Grid size:** 36 combinations per C value
- **Max iterations:** 10,000
- **Estimated runtime:** 5-10 minutes (Chr19)
- **Estimated CV fits:** ~540

Good balance between speed and validation. Tests multiple gamma values
and calibration methods.

### `training_quick.yaml` - Quick Validation
**Use for:** Smoke testing, rapid prototyping, sanity checks

Minimal configuration for fastest possible runs:
- **Rounds:** 2 refinement rounds
- **CV folds:** 3-fold cross-validation
- **Grid size:** 4 combinations per C value
- **Max iterations:** 20,000
- **Estimated runtime:** 10-20 minutes (Chr19)
- **Estimated CV fits:** ~108

Only tests core gamma parameters with fixed "good" values for other
hyperparameters. Use for quick sanity checks.

## Usage

### Train Mode (recommended)

```bash
# Use default config (production) - train only
intronIC train -n homo_sapiens \
  --optimizer-config config/training_default.yaml -p 12

# Use fast test config - train only
intronIC train -n homo_sapiens \
  --optimizer-config config/training_fast_test.yaml -p 8

# Use quick config - train only
intronIC train -n homo_sapiens \
  --optimizer-config config/training_quick.yaml -p 4
```

### Classify Mode with Training

```bash
# Use default config (production) - classify + train
intronIC classify -g genome.fa.gz -a annotation.gff3.gz -n species_name \
  --train --optimizer-config config/training_default.yaml -p 8

# Use fast test config - classify + train
intronIC classify -g genome.fa.gz -a annotation.gff3.gz -n species_name \
  --train --optimizer-config config/training_fast_test.yaml -p 4
```

### From Python

```python
from classification.config_loader import load_optimizer_config

# Load config
optimizer = load_optimizer_config('config/training_default.yaml')

# Use as normal
parameters = optimizer.optimize(u12_introns, u2_introns)
```

### Override Specific Settings

You can override individual settings from the config file:

```python
# Load config but override n_jobs
optimizer = load_optimizer_config(
    'config/training_default.yaml',
    n_jobs=4  # Use 4 cores instead of -1 (all cores)
)
```

## Creating Custom Configurations

To create a custom configuration:

1. **Start with `training_default.yaml`** as a template
2. **Modify sections** based on your needs:
   - Reduce `n_rounds` for faster optimization
   - Reduce `cv_folds` for faster validation
   - Reduce grid parameter lists for fewer combinations
   - Reduce `max_iter` if convergence warnings don't appear
3. **Test with Chr19** data first to estimate runtime
4. **Document** what you changed and why in comments

### Example: Custom Config for New Species

```yaml
# Custom config for species distant from reference data
# Uses more thorough CV but reduced grid for speed

optimizer:
  n_rounds: 5          # Keep thorough refinement
  cv_folds: 10         # Increase for better variance estimate
  n_jobs: -1
  verbose: true
  max_iter: 100000
  n_points_initial: 13
  n_points_refine: 100

param_grid:
  # Test wide range of gammas (distant species may differ)
  estimator__augment__gamma_5_bp: [1, 2, 4, 8, 16]
  estimator__augment__gamma_5_3: [1, 2, 4, 8]

  # Fix other parameters to good defaults for speed
  estimator__svc__dual: [false]
  estimator__svc__intercept_scaling: [1000.0]
  method: ['isotonic']  # Better for non-standard calibration
```

## Configuration Sections

All config files support these sections:

### `optimizer`
Core optimization settings:
- `n_rounds`: Geometric refinement rounds (1-5)
- `n_points_initial`: Initial grid points for round 1
- `n_points_refine`: Refinement grid points for rounds 2+
- `cv_folds`: Cross-validation folds (2-10)
- `n_jobs`: Parallel jobs (-1 = all cores)
- `verbose`: Print detailed progress (true/false)
- `max_iter`: Maximum SVM solver iterations

### `param_grid`
Hyperparameters to search:
- `estimator__augment__gamma_5_bp`: 5'SS-BPS correlation penalty
- `estimator__augment__gamma_5_3`: 5'SS-3'SS correlation penalty
- `estimator__svc__dual`: Primal vs dual formulation
- `estimator__svc__intercept_scaling`: Intercept regularization
- `method`: Probability calibration method

### `c_bounds` (optional)
Override automatic C bounds computation:
- `eff_C_pos_range`: Effective C range for positive class
- `eff_C_neg_max`: Cap on effective C for negative class

### `reference_subsample` (optional)
Subsample reference data for ultra-fast testing:
- `u12_fraction`: Fraction of U12 references to use (0.0-1.0)
- `u2_fraction`: Fraction of U2 references to use (0.0-1.0)

## Performance Comparison

| Config | CV Fits | Runtime (Chr19) | Grid Size | When to Use |
|--------|---------|-----------------|-----------|-------------|
| `training_default.yaml` | ~9,360 | 20-40 min | 144 | Production, publications |
| `training_fast_test.yaml` | ~540 | 5-10 min | 36 | Development, testing |
| `training_quick.yaml` | ~108 | 10-20 min | 4 | Smoke tests, sanity checks |

*Runtime estimates are for Chr19 test data on a modern multi-core system with `-p 8` or `n_jobs=-1`.*

## Notes

- **Default behavior:** If no `--optimizer-config` is specified, intronIC uses
  CLI argument defaults which match `training_default.yaml` (except max_iter=50000)

- **Grid search:** The C regularization parameter is always computed automatically
  based on class imbalance. You cannot specify it in the config.

- **Convergence:** If you see convergence warnings, increase `max_iter`. The
  classification will still work, but may be slightly suboptimal.

- **Parallelization:** Using `n_jobs=-1` (all cores) is highly recommended for
  grid search, which is embarrassingly parallel.

## Quick Reference: Which Config Do I Need?

### General Settings → TOML Config (`--config`)
**Use when you want to set:**
- Classification threshold (e.g., 90% vs 95%)
- Number of parallel processes
- Scoring region coordinates
- Output naming conventions
- Isoform selection rules

**Commands:**
```bash
# Generate template
intronIC --generate-config

# Use custom config
intronIC classify -g genome.fa -a annotation.gff -n species \
  --config my_settings.toml
```

**Example:** You're running many analyses and want to always use `-p 8` and `--threshold 95` without typing it every time.

### Training Settings → YAML Config (`--optimizer-config`)
**Use when you want to set:**
- SVM hyperparameter grid (which features to test)
- Cross-validation strategy
- Optimization rounds and grid density
- Parallelization of grid search

**Commands:**
```bash
# Use production settings for training
intronIC train -n homo_sapiens \
  --optimizer-config config/training_default.yaml -p 12

# Use fast settings for development
intronIC train -n homo_sapiens \
  --optimizer-config config/training_fast_test.yaml -p 4
```

**Example:** You're training a model and want to use the new L2-only, 7-feature configuration we just created.

### Can I Use Both?
**Yes!** They control different things:

```bash
# General settings from TOML + Training settings from YAML
intronIC classify -g genome.fa -a annotation.gff -n species \
  --train \
  --config my_general_settings.toml \
  --optimizer-config config/training_default.yaml \
  -p 8
```

The TOML config sets threshold, output options, etc., while the YAML config controls how the SVM is trained.
